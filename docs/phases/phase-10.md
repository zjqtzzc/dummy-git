## 一、交互细节（逐条定）

1. **入口**（已定，2026-10-15）
   - 分支右键 `Push` 改名 `Push…`，只在本地分支上；点了一律开对话框，不再直接推（同 IDEA）。
   - 竖按钮区不加 Push（沿用 10-14 的决定）。提交右键 `Push All up to Here…`、推送被拒后重推仍在池子，以后接到同一个对话框。
2. **对话框的内容与排版**（已定，2026-10-15）
   - 标题 `Push <分支>`，一行说明；目标一行 `<分支> → [远程 ▾] / [远程分支名]`，远程上没有这个分支时后面标 `New`（同 IDEA）。
   - 提交列表：说明、作者、日期三列，给最大高度、框内滚动，点了没反应。否决 IDEA 右侧的文件列表（只排一列）。
   - 上游沿用现规则：本地分支没有上游时自动带 `-u`，不给勾选框。
   - 默认目标：上游 → `origin` → 第一个远程（2026-10-15 第 4 步改：原为「多个远程且没有 origin 时报错」，对话框里看得见、改得了，不必报错）。一个远程都没有时到第 6 步换成定义远程。
3. **要推的提交怎么算**（已定，2026-10-15）
   - 远程分支已存在：`<远程>/<分支>..<本地分支>`；不存在：`<本地分支> --not --remotes=<远程>`（同 IDEA）。改远程或分支名就重算。
   - 为空时显示 `No commits to push`，Push 仍可点（force 时远程可能多出提交）。
   - 不显示 force 会覆盖掉的远程提交（进池子）。
4. **Force push**（部分已定，2026-10-15）
   - 主按钮做成拆分按钮 `[Push | ▾]`（`vscode-button-group`），`▾` 里是 `Force Push`，用 `--force-with-lease`。否决勾选框（用户定）。
   - `▾` 在按钮上方弹出一个浮层，里面是蓝色的 `Force Push` 按钮（写在 `PushApp.vue` 里，别处也要时再抽）。浮层画在 webview 里出不了标签页，所以往上开、右对齐；点了动作、点外面、按 Esc、webview 失焦都收起。
   - 否决 VS Code 原生菜单（点 `▾` 时派发合成的 `contextmenu`，菜单项写在 `package.json`）：试过能弹，但外观是右键菜单那种列表，用户要的是弹出按钮（2026-10-15 用户定）。
   - 选了之后再弹一次原生确认（同 IDEA，用户定）：`Force push to <远程>/<分支>? It may overwrite commits at the remote.`，按钮 `Force Push` + 取消。理由：它藏在下拉里，选的时候看不到警告（Reset 不同：对话框本身就是确认，说明写在按钮旁）。
   - lease 被拒照旧走错误关口；不做 IDEA 的「Force push anyway」（改用 `--force`）。
5. **定义远程**（已定，2026-10-15）
   - 一个远程都没有时，远程下拉换成 `Name`（默认 `origin`）、`URL` 两个输入框；点 Push 先 `git remote add` 再推送，不单设「添加」按钮。
   - 否决 IDEA 的做法：另弹一个小对话框，OK 前校验名字并 `ls-remote` 试连，添加与推送分两步。弹窗里再弹窗不好做；地址错了推送时 git 会报，名字不合法、重名也交给 git 报。
6. **推送时**（已定，2026-10-15，同 IDEA）
   - 点 Push（或确认 Force Push）就关标签页，推送在后台跑；进度在状态栏，成功与失败走现有的进度出口与错误关口，文案不变。对话框没有「推送中」「失败后恢复」的状态。
7. **对话框开着时**（已定，2026-10-15：不做）
   - 内容在打开时算一次，不跟着仓库刷新（对话框只开一会儿；分支中途被删，推送时 git 会报）。
   - 开着时又点另一个分支的 `Push…`：同一种对话框只开一个标签，切过去并按新分支重新填，等于关了重开。
   - 不做 `Esc` 关闭：会和下拉框收起、VS Code 及键位插件的 Esc 绑定冲突；关标签页已有 `Ctrl+W`。

不做：选仓库（现阶段只支持单仓库，tech/architecture.md 第 13 题）；推送 tag、Run Git Hooks 开关（池子里已有）；推送被拒后 Rebase & Push / Merge & Push（池子里已有）。

## 二、实现顺序

每步一个概念，`pnpm check` 通过、手动看过、用户确认后单独提交。

1. **对话框外壳**：第三块 webview 开在编辑器标签页（`createWebviewPanel`），同一份打包按视图挂根组件；通用外壳 `DialogShell.vue`（标题、内容、贴底按钮栏、宽度规则）。分支右键改 `Push…`，打开后显示 `Push <分支>` 与一行说明，`Cancel` 关标签，Push 点了没反应；同一种对话框只开一个标签（再开换成新分支）。分支名经 HTML 的 `data-subject` 带给页面。
2. **Push**：显示目标（只读，用现有的默认目标）；点 Push 就关标签，按对话框里的目标推送（沿用现有的 `push` 与进度、错误出口）。分支右键不再直接推。
3. **拆分按钮与 Force Push**：`[Push | ▾]`，`▾` 往上弹出 `Force Push` 按钮；原生确认后 `push --force-with-lease`。推送前由扩展关对话框（确认取消时对话框留着）。
4. **选远程、改远程分支名**：远程下拉 + 分支名输入框，远程上没有时标 `New`。
5. **要推的提交**：列表（说明、作者、日期），改目标就重算；为空显示 `No commits to push`。
6. **定义远程**：没有远程时换成 `Name` / `URL` 输入框，Push 时先 `git remote add`。手测场景要加一个没有远程的仓库。
7. **验收**：「要核对的条目」逐条勾过；验收句手动走一遍；`pnpm check`；本文状态改为完成。
