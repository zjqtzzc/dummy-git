# 第 2 阶段细节：提交

状态：完成（2026-09-30）。需求条目与 tech/architecture.md 第 2、4、12、14、15、16 题逐条核对过；`pnpm check` 通过（377 个测试）。
验收句：侧栏 Commit 面板打开，看到未提交的文件树，勾选文件、写说明，提交或 Amend；勾选后 Rollback 直接删除已跟踪文件的改动。提交后底部 Log 自己出现新提交。不推送，不 stash，不切分支。

结束标志：`pnpm check` 通过，验收句手动走一遍成立。

## 一、树：共同部分抽成基础组件

所有树（Log 左栏分支树、Log 右栏文件树、Commit 面板，以后的 Stash）共用一个自己画的基础组件，外观与交互照 VS Code 原生的树。不用 vscode-elements 的 `vscode-tree`：它只给一个 22px 的图标位、不发展开事件、行的点击与焦点在它内部、没有虚拟滚动——复选框、收起子目录、跟随 diff 每一样都得绕着它做，复选框终于绕不过去（点不上、被裁掉）。

| 方面 | 分支树 | Log 右栏 | Commit 面板（第 2 / 4 / 7 阶段） | 归属 |
|---|---|---|---|---|
| 数据 | 分支、tag、HEAD | 一条提交的改动 | 工作区未提交改动（含未跟踪）；第 7 阶段加冲突；第 4 阶段 Stash 模式是各 stash 的文件 | 各自，转成统一的 `TreeNode` |
| 行 | 22px；缩进、箭头、图标、文字 | 同，外加说明、右侧字母 | 同，外加复选框 | 共同 |
| 图标 | codicon（当前分支黄色标签） | Seti | Seti；组标题无图标 | 各自给，基础组件只画 |
| 展开 | 按保存的状态 | 全部展开 | 全部展开 | 共同；初始状态与保存各自 |
| 收起 | 收起时子节点一起收起，再展开只露出一层；全部展开 / 收起 | 同 | 同 | 共同 |
| 键盘、点击 | 上下移动，左收起 / 回父，右展开，回车打开；单击选中，双击打开 | 同；选中变了 diff 跟随，打开即打开 diff | 同 | 操作共同；做什么各自 |
| 复选框 | 无 | 无 | 文件、目录、组都有，勾上级等于勾全部，部分勾选为半选，刷新后保持；第 7 阶段冲突组没有 | 基础组件的可选能力 |
| 分组 | 本地 / 远程 | 无 | `Changes` / `Unversioned Files`；第 7 阶段 `Conflicts`；第 4 阶段每个 stash 一组 | 不是特别的东西：没有图标、文字加粗的上级节点 |
| 右键 | 第 4 阶段 | 无 | 第 7 阶段 | 基础组件只给出口，菜单各自做 |
| 数量 | 几百 | 通常不多 | 未跟踪可能成千上万 | 共同：虚拟滚动 |

**拆法**

1. **统一节点 `TreeNode`**：id（树内唯一）、文字、是否加粗、图标（codicon，可带展开后的另一个；或 Seti 字形；缺席即无图标）、文字颜色、说明、右侧字母、子节点（有即可展开）、这一支不要复选框。使用方把自己的数据转成它，「类型 → 图标 / 颜色 / 字母」表各自持有（CLAUDE.md B.3）。不用插槽：图标等都是数据，组件里没有往别人插槽塞东西的问题。
2. **纯逻辑 `logic/tree/tree.ts`**：按展开状态压平成行（层级、有无箭头、是否展开）；收起时连子节点一起收起；全部展开 / 收起；键盘的父节点、上下行；复选框由勾选的叶子集合推出全选 / 半选 / 未选。
3. **基础组件 `tree/Tree.vue`**：虚拟滚动（`virtualList.ts`）、行的外观、焦点留在容器上（同提交列表）、键盘与点击。可选能力：
   - 展开状态由使用方持有（`v-model:expanded`）：分支树按自己的默认值并存进 `viewState`；文件树新出现的目录默认展开。收起时连下面一起收起由基础组件算好再交回。
   - `checked`（勾选的叶子 id）+ 事件 `check(ids, value)`：给了才画复选框，勾选状态由使用方持有。
   - 事件 `select(node)`（选中行变了）、`activate(node)`（双击、回车）；以后 `contextmenu(node)`。
   - 多选：以后要（批量操作），现在没有使用方，不做。到时选中由一个 id 改成集合，只动 `tree/Tree.vue`。
4. **留在使用方**：数据来源与转换、图标与配色、打开 diff 的左右、展开状态的保存、勾选后做什么（提交、Rollback）。
5. **文件树**（Log 与 Commit 共用）是基础组件之上的一层：`FileEntry` 分组整理成树（`logic/tree/fileTree.ts`：目录合并、`N files`、目录在前、按名字排序），再转成 `TreeNode`。组的 id 加上路径里不会出现的前缀，免得和同名目录撞。

## 二、交互细节

1. **面板位置**：活动栏上 Dummy Git 自己的按钮与图标，点开是侧栏的 Commit 面板。不挂进源代码管理（永不做清单），也不挂进资源管理器等别人的容器。图标沿用底部面板的 `resources/log.svg`。
2. **面板布局**，从上到下：
   - 顶部：Commit / Stash 切换栏。本阶段先占位：两个标签都画出来，Stash 置灰不可点，第 4 阶段接上（它一定会做，且决定布局高度，占位成本低），下面一行工具栏：Rollback（作用于勾选的文件，远离提交按钮防误点）、全部展开 / 收起。不设刷新按钮，文件变动由 watcher 自动刷新。
   - 文件树：占满剩余高度，可滚动。
   - 底部固定区：Amend 复选框、提交说明输入框（默认几行高，可拖高）、Commit 按钮。始终贴底，不被文件树挤走。
3. **改动类型**：底层照常用暂存区，界面不区分，只看 HEAD ↔ 工作区文件。新增（不论是否 add）为 A，删除（不论 rm 还是 git rm）为 D，其余为 M。add 后又在磁盘删掉（`AD`）的不显示，也不自动清理暂存区（同 IDEA；后台写操作会和用户终端里的 git 抢锁）。数据来自一条 `git status --porcelain=v2 --untracked-files=all`（未跟踪文件逐个列出，不折叠成目录），由两列合成。提交时勾选的文件按工作区现状整个提交，其余路径的暂存区保持原样。
4. **默认勾选**：全都不勾。每组标题行（如 `Changes  N files`）带复选框，勾它等于全选该组。宁可多点一下，不要误提交垃圾文件。
5. **分组**：按改动性质分组，从上到下 `Conflicts`（第 7 阶段，无复选框）、`Changes`（已跟踪的 A / M / D）、`Unversioned Files`（未跟踪）。空组不显示。每组各自一棵目录树，各自全选。
6. **刷新后的勾选**：勾选按路径保持；消失的路径移出勾选集合；新出现的一律不勾（原本全选的组因此变半选，提醒有没勾的新文件）。
7. **提交说明**：说明为空（只有空白也算）或一个文件都没勾时，Commit 按钮置灰（Amend 例外见第 8 条）。说明框内容在面板隐藏 / 窗口重载后保留，只有提交成功才清空，失败不清。说明原样提交，只去首尾空行，经 `git commit -F -` 从 stdin 传入。
8. **Amend**：
   - 勾上：当前输入存为普通草稿，说明框换成 HEAD 的说明——每次都重新取，不保留上次 Amend 时改到一半的内容。取消勾选：说明框换回普通草稿，没有就清空。
   - 仓库还没有提交时 Amend 置灰。一个文件都没勾也能 Amend（只改说明），此时 Commit 按钮只看说明是否为空。
   - 不检查上一个提交是否已推送（第 2 阶段不涉及推送）。
   - 保存：Amend 是否勾选、说明框当前内容、普通草稿，每次输入后停手 300ms 写入 `viewState`（webview 没有可靠的关闭事件，不能等关闭时再存）。切面板、重载窗口原样恢复。
   - 成功后：说明框与普通草稿都清空；Amend 成功顺带取消勾选。失败都不动。
9. **Rollback**：只管已跟踪的改动（`Changes` 组），恢复成 HEAD 的样子，新增的文件连磁盘上的一起删；勾选里的未跟踪文件不动，一个已跟踪文件都没勾时置灰（未跟踪文件用第 7 阶段右键菜单的 Delete）。确认用 VS Code 原生模态框，写明文件数，列出前 5 个文件名（更多时以 `…` 结尾），按钮 `Rollback`，另有取消。带文件树、可改勾选的确认页进池子。
10. **双击打开的 diff**：左 HEAD 版本（只读），右工作区真实文件（`file:`，可直接编辑保存）。A 与未跟踪左边空；D 右边空。沿用 `DiffSide`（`Revision` / `Missing`），加一种「工作区文件」。标题如 `foo.ts (1a2b3c4 ↔ Working Tree)`：左边写 HEAD 的短 hash，同 Log 的写法。HEAD 的 hash 由 `getStatus` 顺带给出（`status --branch`），与改动同一次调用；URI 里只放完整 hash，历史版本内容才永远不变。打开 / 跟随规则与 Log 右栏相同（基础类负责）。
11. **快捷键**：宁缺毋滥，只有说明框里 Ctrl+Enter（Mac 上 Cmd+Enter）= 点 Commit 按钮（置灰时无效，勾 Amend 时即 Amend）。webview 内监听，不在 `package.json` 注册。Rollback 不设快捷键。
12. **进行中 / 成功 / 失败**：进行中 Commit 与 Rollback 按钮置灰，Commit 按钮文字变 `Committing…`，说明框与复选框照常可操作（按钮状态靠等请求返回，Router 保证恰好回一次）。成功不弹通知，结果本身可见。失败走 gate（通知 + 输出面板），面板上不另显示，说明与勾选原样保留。
13. **没有改动**：文件树区域正中一行灰字 `No changes`（空组本就不显示）。工具栏与底部固定区照常，Rollback、全部展开 / 收起置灰；说明框与 Amend 可用（可只改上一次说明）。非仓库 / git 不可用时侧栏显示第 1 阶段已有的「不可用」页。

## 三、实现顺序

每步一个概念，`pnpm check` 通过、手动看过、用户确认后单独提交。

1. **文件树改成 `FileEntry`**：`logic/tree/fileTree.ts` 与 `FileTree*.vue` 只认 `FileEntry`；「改动类型 → 字母 / 颜色」表挪到 Log 这边，由 Log 把 `CommitFileChange` 转过去。Log 行为不变。
2. **收起时子目录一起收起**：文件树与分支树都改，监听 `open` 属性，收起时去掉下面各项的 `open`（6b 起由基础组件接管）。
3. **侧栏 Commit 面板的壳**：活动栏容器（`log.svg`）+ webview 视图；HTML 拼装与「不可用」页和 Log 共用，页面按视图挂不同的根组件。只有布局：切换栏（Stash 置灰）、工具栏、空的树区、底部固定区，都还不能用。
4. **文件树分组**：基础类加分组（标题行 `名称  N files`，空组不显示），纯逻辑配测试。
5. **显示工作区改动**：协议加 `getStatus`；Commit 面板把 `FileChange` 转成两组（`Changes` / `Unversioned Files`，`AD` 不显示，未跟踪 `U`）；`worktree` / `index` 等域过期时重拉；没有改动时 `No changes`。
6. **树基础组件**，分三步：
   - 6a：`logic/tree/tree.ts` + `tree/Tree.vue`，Log 右栏换上去，行为不变。
   - 整理目录：按功能分 `tree/`、`log/`、`commit/`，`logic/` 下同样分；多处共用的（`client`、`protocol.guards`、`virtualList`）留在 `logic/` 根上。只搬文件，不改行为。
   - 6b：分支树换上去，删掉 `treeCollapse.ts`，项目里不再用 `vscode-tree`。
   - 6c：复选框。勾选联动的纯逻辑配测试；Commit 面板勾选按路径保持、新文件不勾，存进 `viewState`。
7. **工作区 diff**：`getStatus` 顺带返回 HEAD；`DiffSide` 加「工作区文件」（`file:` URI，可编辑），标题 `<短 hash> ↔ Working Tree`；Commit 面板双击 / 跟随打开。
8. **全部展开 / 收起**两个按钮（基础组件已有，接到工具栏）。
9. **提交**：说明框、Commit 按钮与置灰规则、`Committing…`、Ctrl+Enter、草稿保存。扩展侧补上未跟踪文件先 `add` 再 `commit --only`，两条排在一起、前一条失败后一条不跑。
10. **Amend**：取 HEAD 说明、切换时换草稿、`commit --amend --only`（不勾文件即只改说明）、没有提交时置灰。
11. **Rollback**：原生模态确认（文件数 + 前 5 个）；一条 `restore --source=HEAD --staged --worktree`，改名的带上旧路径；最低 git 版本因此提到 2.23。
12. **补漏**（验收时核对 ARCHITECTURE 发现）：
   - 12a：要密码时直接报错（第 16 题）：`GIT_ASKPASS` / `SSH_ASKPASS` 指向只 `echo ''` 的脚本，`SSH_ASKPASS_REQUIRE=force`。
   - 12b：提交失败撤回 `add`（第 14 题第 3 步）：`commit` 失败后 `reset -q --` 刚 `add` 的未跟踪文件。
13. **验收**：ARCHITECTURE 里「首次用到：第 2 阶段」的题目逐条核对；验收句手动走一遍，`pnpm check`，本文状态改为完成。

## 四、留给后面的阶段

- **右键菜单**（第 7 阶段）：树基础组件只留出口，菜单各自做。未跟踪文件的 Delete 一起做——Rollback 只管已跟踪的改动。
- **多选**（以后，批量操作）：选中由一个 id 改成集合，只动 `tree/Tree.vue`。
- **键盘空格勾选**：没做，快捷键宁缺毋滥；需要时在 `Tree.vue` 的按键处理里加。
- **未跟踪文件成千上万**：树已是虚拟滚动，但 `git status -uall` 与勾选推算仍是全量，退化方案在需求池。
- **冲突组**（第 7 阶段）：`workingFiles()` 现在跳过冲突文件；那时加 `Conflicts` 组（无复选框，`TreeNode` 加「这一支不要复选框」）。
- **Stash 切换**（第 4 阶段）：顶部切换栏已占位，Stash 置灰。
- **Amend 会变成空提交**时 git 拒绝，走错误关口显示原文，不处理（不加 `--allow-empty`）。
- **分支树**已换到树基础组件；双击筛选 Log 在第 5 阶段接 `activate` 事件。
