## 一、交互细节（逐条定）

1. **图的宽度**（已定，2026-10-14，照 IDEA §7.1、§7.4）
   - 没有单独的 Graph 列：图画在 Message 单元格的最左边，文字往右推出本行图的宽度；表头仍是 Message / Author / Date。Author、Date 宽度固定，不受影响。
   - 每行的宽度各自算：`max(本行最右元素的位置 + 1, 基准) × 车道宽 + 间隔`。斜线在本行只画一半，按两端位置的平均值计。
   - 基准 = min(6, 推荐宽度)。推荐宽度 = 各行宽度的加权平均 + 一个标准差，靠上的行权重大（最上一行是最下一行的 10 倍）。比基准窄的行文字对齐到基准，比基准宽的行文字单独往右退。
   - **长线隐藏中间**：跨度 ≥ 30 行的线只在两头各露 1 行，带箭头，中间不画、不占位置。没有它，老历史里拉上来的长线会让大部分行都比基准宽。「显示长线」开关仍在需求池里，这一阶段总是隐藏。
   - 实现：布局输出每行的宽度与基准；渲染时每行用行内样式给出图的宽度，Message 本来就是 `minmax(0, 1fr)`。
   - 否决：整列一个公共宽度、只有超出上限的行退让（老历史的长线让上限形同虚设）；按可见行定宽（滚动时整列跳）；固定宽度。

2. **几何尺寸**（已定，2026-10-14，照 IDEA §7.1）
   车道宽 16px，节点直径 8px 的实心圆，线宽 1.5px，图与文字间隔 2px；行高同为 22px。合并提交的节点与普通提交一样。
   HEAD 所在提交的节点画成「外圈 + 实心」（IDEA §7.3）不做，进需求池。

3. **折角的形状**（已定，2026-10-14，照 IDEA §7.3）
   每段线从本行节点中心直线画到相邻行目标位置的中心，超出本行的部分被裁掉；上下两行各画一半，拼成一条跨一行的斜线。不换位置的是竖线。全是直线。
   否决直角（先竖再横再竖）：线多时横段和穿过的竖线重叠，分不清是谁的。

4. **车道怎么分**（已定，2026-10-14，照 IDEA §7.2）
   - 整张图编一次号：把「头」（没有子提交的提交与分支指向的提交）排序，从每个头出发沿第一父提交往下走，沿途提交拿同一个编号。
   - 头的排序：`origin/main|master` → 其它远程分支 → `main|master` → 本地分支 → tag → detached HEAD；同类按名字。主干排最左，当前分支不特殊对待。
   - 每一行把本行的节点和穿过的线按编号排序，位置就是序号；左边有线结束时右边的线自动左移一格。**车道永远是压缩的。**
   - 我们的骨架从 `HEAD --branches --remotes --tags` 出发，每个头上都有 ref，`getRefs` 的结果就够排序。
   - 推论：编号依赖 refs，refs 变了要重算布局（不一定重拉骨架，见实现顺序第 7 步）。
   - 否决固定车道（线占住一条车道就不挪）：斜线少，但留空列，图更宽，与第 1 条的基准宽度冲突。

5. **颜色**（已定，2026-10-14）
   - 分配规则照 IDEA §7.5：编号是某个分支的主链时，颜色 id = 分支名的 hash（同一个分支永远同一个颜色）；分叉出来的片段，颜色 id = 编号。线的颜色取两端里编号较大的那个节点。
   - 头上没有 ref 的主链用默认色（照 IDEA 的 `DEFAULT_COLOR`；IDEA 是黑色，我们用 `descriptionForeground`）。
   - 调色板 17 种，全是主题变量：`scmGraph.foreground1`–`5` + 终端的红绿黄蓝品红青各两档（不用黑白）。颜色 id 对调色板长度取余。变量缺失时用后备颜色，不调高最低版本。（2026-10-14 由 5 种扩充：5 种时每 5 个分支就撞一对。）
   - 否决照 IDEA 用 HSL 算颜色：颜色多，但「看得清」变成我们的责任，深浅高对比要各配参数，且违背 tech/architecture.md 第 20 题。IDEA 实际也只有片段 10 种色相。
   - 否决 `color-mix()` 混中间色：混出的颜色与两边原色接近、易发浊。否决「相邻车道避开同色」：颜色不再只由分支决定。
   - 已知代价：只有 5 种，相邻的线可能撞色。

6. **截断处**（已定，2026-10-14）
   父提交不在列表里的线（第一万条附近）从节点画到行底，**逐渐变淡**（SVG 线性渐变，透明度从 1 到 0），不加箭头。
   和长线的箭头区分开：箭头是「下面还连着，中间省略了」，渐隐是「到这里为止，后面不在列表里」。
   否决照 IDEA 画向下箭头（`NOT_LOAD_COMMIT`）：IDEA 是还没加载、往下滚会出现；我们是截断，往下滚也看不到，用同一种画法会让人以为能接上。

7. **ref 标签**（已定，2026-10-14，照 IDEA §7.7）
   - 位置：靠右，画在 Message 单元格最右边；起点 = max(本行图宽, 单元格宽 − 标签总宽)。
   - 空间：说明文字至少保留 80px；标签可用宽度取「文字区的一半」与「文字区 − 80px」的较大者。
   - 截断：标签名放不下且超过 22 个字时，第一个 `/` 前换成 `..`，末尾加省略号。
   - 合并：本地分支和它跟踪的远程分支合成一个标签（2026-10-14 从「永不做」拿出来）；当前分支排第一。
   - 顺序：当前分支 → `main|master` → `origin/main|master` → 本地分支 → 远程分支 → tag。
   - 合并后显示「远程 & 本地分支」（同 IDEA，如 `origin & develop`），条件是 upstream 指向的远程分支在同一个提交上。
   - 外观：无边框，字号小一档；codicon 区分类型，图标按主题色着色——当前分支 `charts.yellow`、本地 `charts.green`、远程 `charts.purple`、tag `descriptionForeground`、detached HEAD 用 `warning` 图标 + `editorWarning.foreground`。
   - 放不下时从后往前截：收缩系数按位置 100 的幂递增（封顶 100⁴），每个标签最窄剩图标。
   - 数据：`LogApp.vue` 已经拉了 `getRefs`，不加新命令。
   - 否决紧跟在图后面：说明文字的起点随标签多少左右跳。否决只显示前几个写 `+N`：IDEA 的截断已够用，少一个悬停交互。

8. **筛选时的虚线**（已定，2026-10-14，照 IDEA §7.6）
   - 在完整的图上隐藏不匹配的提交，从上往下、从下往上各扫一遍，每个可见提交与沿被隐藏路径能到达的**最近**可见提交连一条虚线。线性时间。
   - 经过不同的被藏路径能到好几个可见祖先时，只连最近的一个（IDEA 的简化，换线性时间）。
   - 编号沿用完整图，车道顺序与不筛选时一致；被隐藏的行不占位置。
   - 日期筛选一视同仁：布局的输入是筛选后的 hash 列表，不管是哪种条件筛掉的。
   - 一直找不到可见的祖先：虚线画到行底并渐隐，同截断处。
   - 虚线与长线隐藏同时生效：跨度 ≥ 30 行一样只画两头。
   - 分支筛选换的是骨架，图照常画，不涉及虚线。
   - 否决每条被藏路径通向的可见祖先都连：要逐个搜索，最坏不是线性，多出的线也让图更乱。

9. **鼠标与键盘**（已定，2026-10-14）
   点图上任何位置就是选中这一行，和点 Message 一样；节点和线不单独响应点击、不加粗、不显示悬停提示。
   否决照 IDEA 点节点或线加粗相连的线（§7.3）：需求里没有，也不进需求池。沿着图在父子之间跳的键盘导航在需求池里，不做。

## 三、技术方案（已定，2026-10-14）

### 1. 数据流

```
扩展侧（不改）                       webview
getSkeleton ──► skeleton ─┐
getRefs ──────► refs ─────┼─► ① 图结构 + 编号 + 颜色（骨架或 refs 变了才重算）
                          │            │
applyFilter ──► hashes ───┴────────────┴─► ② 可见图（筛选变了重算：虚线、截断）
                                                    │
                                                    ▼
                                           ③ 每行的元素与位置、行宽、基准
                                                    │
                                    CommitList.vue ◄┘  只画可见那几十行的 SVG
refs ─► ④ 标签分组（按提交 hash）─────► CommitList.vue  Message 单元格右侧
```

- 扩展侧和协议都不动：骨架、refs 早就有，筛选结果 `hashes` 也已经在 `LogApp.vue` 里算好。
- ①②③④ 全是 `webview/src/logic/` 里的纯函数，不 import `vue`，纯 node 测试。`LogApp.vue` 用 `computed` 串起来，Vue 组件只摆数据。
- 全部在主线程一次算完全部行（不按可见行懒算）：推荐宽度本来就要所有行的宽度。一万条预计几到几十毫秒，第 4 步实测；超了再改成按需算每行的元素（宽度仍全量）。

### 2. 模块（`webview/src/logic/log/graph/`）

| 文件 | 做什么 | 输入 → 输出 | 估计行数 |
|---|---|---|---|
| `structure.ts` | 骨架转成按行号的图：每行的父行号、子行号；父提交不在骨架里的记成「缺失」 | 骨架 → 行号图 | 60 |
| `layout.ts` | 头的排序（ref 类型 → 名次的表放这里）+ 沿第一父提交编号 | 行号图 + refs → 每行的编号 | 90 |
| `color.ts` | 颜色 id：主链用分支名的字符串 hash，片段用编号。只给身份，不取余：几种颜色由 `GraphCell.vue` 的调色板决定 | 编号 + refs → 每行的颜色 id（非负整数） | 20 |
| `visible.ts` | 筛选后的可见图：直接父子相连是实线；中间隔着被藏的提交是虚线（两趟线性扫描）；父提交缺失或找不到可见祖先记成「渐隐」 | 行号图 + 可见集合 → 可见图的边 | 110 |
| `rows.ts` | 每行有哪些元素（本行节点 + 穿过本行的边）；跨度 ≥ 30 的边只留两头并标箭头；按编号排序得位置；每段线在相邻行的目标位置；行宽；推荐宽度与基准 | 可见图 + 编号 → `GraphRow[]` + 基准 | 200 |
| `types.ts` | 输出类型与 enum 的声明（不放数据表） | — | 40 |

不筛选时 `visible.ts` 退化成「全部可见、全是实线」，走同一条路，不写特例。

### 3. 输出给界面的形状

```ts
enum LineStyle { Solid = 'solid', Dotted = 'dotted' }
/** 线在本行的那一头怎么收：接到相邻行、画箭头（长线省略处）、渐隐（截断或找不到可见祖先）。 */
enum LineEnd { Joined = 'joined', Arrow = 'arrow', Fade = 'fade' }
enum Direction { Up = 'up', Down = 'down' }

interface GraphSegment {
  readonly from: number;      // 本行里的位置
  readonly to: number;        // 相邻行里的位置（Fade 时等于 from）
  readonly direction: Direction;
  readonly style: LineStyle;
  readonly end: LineEnd;
  readonly color: number;     // 颜色 id，界面取余
}
interface GraphRow {
  readonly node: { readonly position: number; readonly color: number };
  readonly segments: readonly GraphSegment[];
  readonly width: number;     // 车道数，可以是 .5（斜线按半格算）
}
interface Graph { readonly rows: readonly GraphRow[]; readonly base: number }
```

`rows` 与列表的 `hashes` 一一对应（同一个下标）。字段的消费者都在 `CommitList.vue` 的画图代码里。

### 4. 渲染（`CommitList.vue` + 一个小组件 `GraphCell.vue`）

- 每行最左一个绝对定位的 `<svg>`，宽 = `max(width, base) × 16 + 2`，高 22。每个 segment 一条 `<line>`：从本行节点中心画到相邻行目标位置的中心（y = ±22 + 11），超出本行的部分由 SVG 自己裁掉；节点一个 `<circle>`，最后画，盖在线上。
- 虚线：`stroke-dasharray`。箭头：线头加两条短线（照 IDEA 的角度与长度）。渐隐：一个全局共用的 `<mask>`（白到黑的线性渐变）套在线上，与颜色无关，只定义一次。
- 颜色 id 对调色板长度取余 → `var(--vscode-scmGraph-foreground1, <后备色>)`：调色板放在 `GraphCell.vue` 里（CLAUDE.md B.3）。用内联 `style` 而不是 SVG 属性（属性里的 `var()` 不保证生效）。
- Message 单元格加 `padding-left` = 图宽；里面改成 flex：说明文字（`flex: 1`、`min-width: 80px`、省略号）+ 标签区（`flex: none`、`max-width: max(50%, 100% − 80px)`）。Author、Date 两列不动。
- 节点和线不挂事件，点击照旧落到行上（第 9 条）。

### 5. ref 标签（`logic/log/refLabels.ts` + `CommitList.vue`）

- 按提交 hash 分组；同一提交上，本地分支和它的上游（`Ref.upstream` 的 remote/name 与某个远程分支相同）合成一个标签；当前分支排第一；其余按第 7 条的顺序。输出 `Map<hash, Label[]>`，标签带 kind（决定 codicon 图标）与显示名。
- 截断的简化：超过 22 个字时，把第一个 `/` 前换成 `..`——纯字符串处理，不量文字宽度；剩下的由每个标签的 CSS 省略号处理。IDEA 是先量宽度、放不下才截；我们省掉量宽度，代价是窄屏时可能截得比必要的多一点。
- 估计：逻辑 80 行，界面 50 行。

### 6. 骨架没变沿用旧数组（`LogApp.vue` 的 `load`，同 vscode-git-graph）

- refs 过期照样并行拉 refs 与骨架；骨架逐条比 hash、父提交、提交时间（`sameCommit`），全同就沿用旧数组——图结构不重算、筛选不重查。
- 省的是 webview 侧，不省 `git log` 与传输。
- 否决「ref 指向的 hash 集合没变就不拉」：`shallow`、`refs/replace` 不动 ref 却改图，会显示过时的图。否决 IDEA 的增量拼接：拼接与回退逻辑远超收益。

### 7. 复杂度与风险

合计约 700 行代码（逻辑约 520、界面约 180），另加测试。

| 部分 | 难度 | 风险 |
|---|---|---|
| `structure` / `layout` / `color` | 低 | 头的排序规则要和 refs 的建模对上（detached HEAD、tag 指向非提交已在 `Ref` 里处理） |
| `visible`（虚线） | 中 | 两趟扫描的正确性只能靠测试兜：要覆盖菱形、连续被藏、多父合并 |
| `rows`（位置与宽度） | **高** | 元素排序比较器决定相邻两行的线对不对得上，照 IDEA 的比较规则（边与边、边与节点按编号比，平局按上端行号）；长线两头与箭头；斜线半格计宽 |
| SVG 渲染 | 低–中 | 渐隐用 mask；高分屏下 1.5px 线可能发虚（IDEA 做了像素对齐，我们先不做，看效果） |
| ref 标签 | 低–中 | 纯 CSS 的空间分配是否够接近 IDEA |
| 骨架没变沿用旧数组 | 低 | 比较漏字段会让图停在旧形状——`sameCommit` 比全了骨架的三个字段 |

评审时接受的三个取舍（2026-10-14）：
1. 全部行一次算完，不按可见行懒算（IDEA 的做法）；第 7 步实测慢了再改。
2. 标签截断不量文字宽度。
3. 线不做像素对齐，看实际效果再定。
