验收句（草拟）：分支树和 Commit 面板的文件能一次选中多个；右键目录或分组，等于对它下面的全部。分支能批量删除、更新；Commit 面板的 Rollback、Add to Git、Delete 作用于选中的项，什么都没选时 Rollback 作用于全部改动。

结束标志：`pnpm check` 通过，验收句手动走一遍成立，下面「要核对的条目」逐条勾过。

## 要解决什么问题

**分支树**：分支越积越多，清理只能一个一个来。
- 一个功能做完，`feat/login/` 下面五个分支都合并了。现在要右键 Delete 五次。
- 想把本地分支都更新到最新，要对每个分支点一次 Update。
- 目录和分组（`Local`、`Remote`、`origin`、`feat/`）现在右键什么都不弹。可「这一组都不要了」恰恰是最常见的清理方式（项目负责人 2026-10-19 提）。

**Commit 面板**：Rollback 现在作用于**勾选**的文件。可勾选是用来挑「这次要提交哪些」的，用户想撤掉一个文件，得先去勾它，撤完还得记得把勾选改回来——两件事挤在一个复选框上。IDEA 的 Rollback 作用于**选中**的文件（项目负责人提，已在需求池）。未跟踪文件的 Add to Git、Delete 也只能一个一个来。

## 难在哪

第 14 阶段解决的「怎么选」「右键菜单拿到整组」，在这里直接复用。树多出来的问题是：

1. **选中的不全是同一种东西**。选中里可能有本地分支、远程分支、当前分支、目录混在一起。菜单里出现什么，要按「每一样都能做」来算。
2. **选中目录等于选中下面全部**，一下子就可能选上几十个分支。Ctrl+A 再点 Delete 就是删光，必须有东西挡住。
3. **确认框会成倍增加**。删一个没合并的分支、删一个远程分支，现在各弹一次确认；选了十个，不能弹十次。
4. **误删要能找回**。现在删一个分支，状态栏和日志里留着 `(was 1a2b3c4)`，靠它找回；一次删十个时，这十个 hash 都得留下。

## 一、分支树

1. **选中目录、分组，等于选中它下面的全部分支**（2026-10-19 项目负责人定）。单独右键一个目录也算。目录、分组指 `Local`、`Remote` 两组，远程名（`origin`），以及按 `/` 折出来的目录。和 IDEA 不同：IDEA 只要选中里有目录，就没有菜单。
2. **多选、目录时菜单里有什么**：只有 Update 和 Delete（同 IDEA）。Checkout、Push…、Merge、Rebase、New Branch、Rename 都只能对一个分支做，名单不止一个分支时不出现。两项都只看名单（`phases/phase-14.md` 第四节 B），不管分支是直接选的还是目录带进来的（待定，推荐）：
   - **Update**：名单里有本地分支就出现，只更新其中的本地分支。
   - **Delete**：名单里有能删的就出现（不是当前分支的本地分支、远程分支），只删能删的，本地远程可以混在一起。右键 `Local` 点 Delete，就是删掉除当前分支以外的全部本地分支。
   - 否决「直接选中的必须全部能做」另一套规则（选了当前分支就不给 Delete）：同一个分支直接选和被目录带进来，结果却不一样，说不清；跳过了哪些，确认框里列的名字看得出来。
   - 竖按钮 Update Selected、Delete Selected 按同一套规则作用于全部；New Branch from Selected 在多选或选中目录时置灰。
3. **远程名和 `Remote` 组不给 Delete**（待定，推荐不给）：删掉一个远程上的全部分支，等于替所有用这个远程的人把它清空，几乎不会是本意。远程名下面的目录（`origin/feat/`）照常能删。否决给、只靠确认框挡：确认框天天点，挡不住手滑。
4. **确认框**（待定）：
   - 单个删除现在的规则：本地分支已合并的直接删，没合并的问一次；远程分支每次都问。多选时规则不变，**合成每类一个确认框**：没合并的本地分支收在一起问一次，远程分支收在一起问一次，框里列出前 5 个名字。先删本地，再删远程（同 IDEA）。否决每个分支各问一次：选十个就要点十次。
   - **选中里有目录时，另加一个总确认框**：
     - A（推荐）：先问 `Delete 12 branches?`，列出前 5 个名字；确认后再照上面的规则走。Ctrl+A 再点 Delete，就被这一框挡住了（难点 2）。
     - B：只问这一次，框里写清哪些没合并、哪些在远程，确认后全删。少点一两次，但单个删除和整组删除就成了两套规则。
     - C：不加总框。全是已合并的本地分支时，一下就删光了，只能从日志里找回。
5. **找回信息不能丢**（推荐）：每个本地分支各跑一条 `git branch -d`，每条各有自己那句 `Deleted branch feat (was 1a2b3c4).`。否决一条命令删多个：git 会输出多行，状态栏消息过 `brief()` 只留第一行，后面几个分支的 hash 就没了；为它给 `brief()` 开例外也不行，截断上限只许在一处定（`CLAUDE.md` G.5）。
6. **批量 Update**（待定）：
   - A（推荐）：按顺序对每个分支走一遍现有的单分支 Update，整体算一次操作。分叉的那几个，各自弹现有的 Rebase / Merge 通知。没有新的交互。
   - B：分叉的收成一条通知，不给按钮。要新写文案，Rebase / Merge 还得回去一个一个点。
   - C：本阶段不做，留在需求池。
7. **做到一半失败了**：比如某个分支被 git 拒绝。已经做完的不撤回，剩下的不再做，显示 git 的报错。日志里每条 git 命令都在，看得出停在哪一个。
8. **不做**：远程名上的 Fetch（只取这一个远程）。竖按钮的 Fetch 已经会取全部远程，进需求池「同步」。

## 二、Commit 面板

9. **Rollback 作用于选中**（同 IDEA）：
   - 工具栏的 Rollback 和右键的 Rollback 是同一件事：撤掉选中的已跟踪改动。选中目录或组标题，等于选中它下面的全部。
   - 选中里没有已跟踪的改动（什么都没选，或者只选了未跟踪文件、冲突文件）时，作用于 `Changes` 组的全部（待定，推荐同 IDEA）。确认框照旧：文件数加前 5 个文件名。另一种做法是这一块不做，单独成一个阶段。
   - 按钮只在 `Changes` 组为空时置灰，不再看勾选。从此勾选只管提交和 Stash。
10. **多选时右键菜单里有什么**：
    - Rollback：选中里有已跟踪的改动就出现，只撤其中已跟踪的（未跟踪文件 Rollback 本来就不管）。
    - Add to Git、Delete：选中的全是未跟踪文件时出现；`Unversioned Files` 组和它下面的目录算作选中下面的全部文件。Delete 只问一次：`Delete 3 files? This cannot be undone.`，列出前 5 个文件名。
    - 冲突文件只能单选（待定，推荐）：它有自己的解决方式（`product/features/conflicts.md`），批量 Accept Ours / Theirs 在需求池「冲突」。

## 三、复制（所有树）

11. **⌘C / Ctrl+C 复制字面值**（2026-10-19 项目负责人定）：选中的每一行复制它显示的文字，多选时按显示顺序一行一个。同 IDEA 的文件树（`ChangesBrowserNodeCopyProvider.java`：每行取显示的文字，用换行连起来；文件是文件名）。
    - 复制的是**看到的那几行**，目录只复制目录名、不展开：和右键菜单的「名单」不同，名单要把目录展开成下面的全部（第 1 条）。
    - 由 `Tree.vue` 统一响应快捷键，各树不再各写一份；`BranchTree.vue` 现在那段按键处理随之删掉。
    - **分支例外，复制全名**（2026-10-19 项目负责人定）：分支树显示的是最后一段（`feat/login/a` 显示 `a`），只有 `a` 贴出去用不了，所以照现在复制 `feat/login/a`；HEAD 那行（显示 `HEAD → main`）照现在复制 `main`。否决严格照字面值。
    - 复制路径（完整路径、相对仓库的路径）不在本条：项目负责人提过「直接复制文件名或路径」，路径要不要另配快捷键还没定。

## 四、技术方案（在第 14 阶段之上多出来的）

- **`Tree.vue` 接上第 14 阶段的选中规则**：所有树都能多选，不设开关（2026-10-19 项目负责人定：默认都要支持多选，才符合操作逻辑）。Stash 多选后能做什么还没想好，现有的 Pop、Apply、Drop 只在右键恰好一个 stash 时出现（同 IDEA 的 `GitSingleStashAction`）；Log 右栏的文件现在没有菜单项，多选的菜单进需求池。选中变了发事件给使用方（竖按钮、Rollback 按钮要用）。
- **展开目录的纯函数**：输入选中的节点，输出要操作的分支或文件，第 2、3、9、10 条的取舍规则都在这里。菜单的 JSON 和竖按钮用同一个函数，配测试。
- **菜单的 JSON** 用第 14 阶段的「名单」形状（`phases/phase-14.md` 第四节 B），名单由同一个共用函数展开目录。各面板加自己的开关键：`dummyGit.canDelete`、`dummyGit.canUpdate`、`dummyGit.canRollback`、`dummyGit.canAdd`，以及 `dummyGit.group`（选中里有目录时写，扩展据此弹第 4 条的总确认框）。
- **协议**：`addUntracked`、`deleteUntracked` 的 `path` 改成 `paths`；`update` 的 `branch` 改成 `branches`；删除合成一条 `deleteBranches`，收本地分支名的列表和远程分支 `{ remote, branch }` 的列表（本地远程混选时，点一下只能对应一条命令）。
