## 一、交互细节（逐条定）

| # | 问题 | 结论 |
|---|---|---|
| 1 | 右栏的文件怎么打开 diff：单击还是双击，用不用预览标签页 | 双击或回车打开。单击或方向键只选中；若插件的 diff 标签正显示在前台（所在编辑组的当前标签），diff 跟着换成选中文件，焦点留在树上；被挡在后面时不翻到前台。插件的 diff 只占一个标签：打开前用 `window.tabGroups` 找到两边是我们 scheme 的 diff 标签并关掉，再打开新的。所有文件树共用这一个「打开 diff」函数。 |
| 2 | 底部面板的标签名和图标 | 视图容器标题 `Dummy Git`，里面一个视图 `Log`；图标用一个 git 提交图形的简单 SVG。 |
| 3 | 左栏：分组默认展开还是折叠；HEAD 行显示什么（含 detached HEAD）；点分支有没有反应 | HEAD 行：在分支上显示 `HEAD → <分支>`，detached 显示 `HEAD (detached at <短 hash>)`。本地组默认展开，当前分支加粗带标记。远程组展开到远程名，`/` 目录默认折叠。每层按名字排序，目录在前。不显示 `origin/HEAD`。展开状态存 `setState`。单击只选中；双击本阶段无反应，第 5 阶段改为按该分支筛选。 |
| 4 | 中间列表：日期格式（绝对时间还是「多久之前」）；作者显示名字还是邮箱；打开时默认选中哪一条 | Message 只显示第一行。Author 只显示名字。Date 用作者时间：一小时内写 `5 minutes ago`，更早写 `2026/9/20 15:51`。打开时选中 HEAD 所在提交并滚到它（列表第一行不一定是 HEAD）。本阶段不显示分支标签。界面文字全部英文。 |
| 5 | 右栏：树默认展开到哪一层；文件的改动类型怎么显示；重命名怎么显示 | 全部展开；单子目录链合并成一行（紧凑目录）；目录后显示 `N files`；目录在前、各按名字排序；文件名用 `--vscode-gitDecoration-*` 配色，右侧字母 `A` / `M` / `D` / `R`；重命名显示新名字，后跟浅色 `renamed from <旧名>`；不加仓库名根行。 |
| 6 | 三栏的初始宽度 | 全程像素，不用百分比：左 240px、右 320px，中间占剩下的全部。拖动后存左右两栏的像素宽度（`setState`），收起再展开、重新加载窗口都恢复。外层 `fixed-pane="start"`、内层 `fixed-pane="end"`：尺寸变化时左右保持宽度。内层分隔线只能从左边定位，挂载后量出宽度再放到「宽度 − 右栏宽度」。 |
| 7 | 刷新时（有新提交、切了分支）保留选中的提交和滚动位置吗 | 选中的提交还在列表里就保持选中，并让它停在屏幕上原来的位置（上方多了新提交时视图不跳）；不在了就改选 HEAD 所在提交。右栏只在选中变了时才重取。 |
| 8 | 加载中显示什么；详情还没取到的行显示什么 | 首次加载：中间栏显示 `Loading…`。详情未取到的行：三列显示浅色占位，取到后替换。右栏取文件时显示 `Loading…`。 |
