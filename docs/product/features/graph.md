# 提交图与 ref 标签

> 提交列表里的图怎么画、ref 标签怎么摆，以及为什么这样做。改 `logic/log/graph/`、`refLabels.ts`、`GraphCell.vue` 前先读本文；行为变了就改本文。
> 照 IDEA 的 Log（`refs/git4idea.md` §7，下文写作「IDEA §7.x」）。

## 排序

过滤栏的 Graph Options（`MenuButton`，图标照 IDEA 新界面的 `intelliSort.svg` 重画成线条，`AppIcon.GraphOptions`）：一节 `Sort`，两个单选项 `By Commit Date`（默认）、`Topologically`，存进 `viewState`（`logic/log/graphOptions.ts`）。同 IDEA 的 Graph Options 里 `Sort` 一节（`VcsLogGraphOptionsChooserGroup.java`，名字见 `VcsLogBundle.properties:326-329`，默认 `PermanentGraph.kt:77` 的 `Options.Default`）。

- 两种排序就是骨架命令的 `--date-order` 和 `--topo-order`（`getSkeleton` 的 `order`），切换就是换参数重取骨架，走现有的刷新（选中留着、视图不跳）。两种都保证父提交排在子提交之后，行号图照常算。
- **和 IDEA 不一样**（2026-10-22 项目负责人定：先按 git 来）：IDEA 的 `Topologically` 是它自己的 IntelliSort，合并进来的那一支紧挨着排在合并提交下面；`--topo-order` 只保证同一支历史不和别的支穿插。IDEA 能这样做，是因为它把全部提交读进内存建成图，排序、过滤都在内存里算，切换不重跑 git。以后可能也迁到内存（`product/backlog.md`）。
- 不做 IDEA 不是默认值时按钮上的小圆点（项目负责人定）。`Options` 一节（First Parent、隐藏合并提交）在需求池。

## 宽度

- 没有单独的 Graph 列：图画在 Message 单元格的最左边，文字往右推出本行图的宽度。表头仍是 Message / Author / Date，Author、Date 的宽度不受影响。
- **每行的宽度各自算**：`max(本行最右元素的位置 + 1, 基准) × 车道宽 + 间隔`。斜线在本行只画一半，宽度按两端位置的平均值算。
- **基准** = min(6, 推荐宽度)。推荐宽度 = 各行宽度的加权平均 + 一个标准差，越靠上的行权重越大（最上一行是最下一行的 10 倍）。比基准窄的行，文字对齐到基准；比基准宽的行，文字单独往右退。
- **长线只画两头**：跨度很长的线（阈值见 `logic/log/graph/rows.ts` 的 `LONG_EDGE`），只在两头各露 1 行，并带箭头；中间的行不画它，也不给它留位置。没有这条，老历史里拉上来的长线会让大部分行都比基准宽。
- 否决：整列一个公共宽度、只有超出上限的行退让（老历史的长线让上限形同虚设）；按可见行定宽（滚动时整列跳动）；固定宽度。

## 形状与颜色

- 尺寸（IDEA §7.1）：车道宽 16px，节点是直径 8px 的实心圆，线宽 1.5px，图和文字之间隔 2px，行高 22px。合并提交的节点和普通提交一样。
- **折角**（IDEA §7.3）：每段线从本行节点的中心，直线画到相邻行目标位置的中心，超出本行的部分被裁掉；上下两行各画一半，拼成一条跨一行的斜线。位置不变的就是竖线。全是直线。否决直角折线（先竖、再横、再竖）：线一多，横段会和穿过的竖线重叠，分不清是谁的。
- **车道**（IDEA §7.2）：
  - 整张图编一次号：先把「头」（没有子提交的提交，以及分支指向的提交）排好序，再从每个头出发，沿第一父提交往下走，沿途的提交拿同一个编号。
  - 头的顺序：当前检出（本地当前分支，游离时是 HEAD）→ 远程分支 → 其它本地分支 → tag，同类按名字。否决按 `main`/`master` 猜主干（2026-10-27 项目负责人定）：默认分支不一定叫这个。
  - 每一行，把本行的节点和穿过的线按编号排序，序号就是位置；左边有线结束时，右边的线自动左移一格。**车道永远是压缩的。**否决固定车道（线占住一条车道就不挪）：斜线少些，但会留空列，图更宽。
  - 编号依赖 refs，所以 refs 一变就重算布局。
- **颜色**（IDEA §7.5）：
  - 编号是某个分支的主链时，颜色 id = 分支名的 hash，同一个分支永远同一个颜色；分叉出来的片段，颜色 id = 编号。一段线的颜色，取两端里编号较大的那个节点。头上没有 ref 的主链用默认色（`descriptionForeground`）。
  - 调色板 17 种，全是主题变量：`scmGraph.foreground1`–`5`，加上终端的红绿黄蓝品红青各两档（不用黑白）。颜色 id 对调色板长度取余；变量缺失时用后备色（取 VS Code 深色主题的默认值），不为此提高最低版本。调色板放在 `GraphCell.vue` 里。主题色与终端色都偏艳，图上统一压低饱和度（IDEA 的提交图饱和度是 0.4）。
  - 否决照 IDEA 用 HSL 现算颜色：「看得清」就成了我们的责任，深色、浅色、高对比主题要各配一套参数。否决只用 5 种 `scmGraph` 色：每 5 个分支就撞一对。否决 `color-mix()` 混中间色：混出来的和两边原色接近，容易发浊。否决「相邻车道避开同色」：颜色就不再只由分支决定了。
- **截断处**：父提交不在列表里的线（一万条附近），从节点画到行底并**逐渐变淡**，不加箭头。箭头的意思是「下面还连着，中间省略了」，渐隐的意思是「到这里为止，后面不在列表里」。否决照 IDEA 画向下的箭头：IDEA 那里是还没加载、往下滚会出现；我们这里是截断，往下滚也看不到。

## 筛选时的虚线

（IDEA §7.6）按作者、说明文字、路径、日期筛选时，只显示匹配的提交；两条匹配的提交之间隔着被跳过的提交时，画虚线相连。
- 在完整的图上隐藏不匹配的提交，从上往下、从下往上各扫一遍，每个可见提交和沿被隐藏的路径能到达的**最近**可见提交连一条虚线。时间是线性的。经过不同的路径能到好几个可见祖先时，只连最近的一个（否决全连：要逐个搜索，最坏不是线性，多出来的线也让图更乱）。
- 编号沿用完整的图，所以车道顺序和不筛选时一致；被隐藏的行不占位置。
- 一直找不到可见的祖先：虚线画到行底并渐隐，同截断处。长的虚线一样只画两头。
- 分支筛选换的是骨架本身，图照常画，不涉及虚线。

## ref 标签

（IDEA §7.7）
- 靠右，画在 Message 单元格的最右边：起点 = max(本行图宽, 单元格宽 − 标签总宽)。说明文字至少留 80px；标签可用的宽度，取「文字区的一半」和「文字区 − 80px」中较大的那个。否决紧跟在图后面：说明文字的起点会随标签多少左右跳。
- 本地分支和它跟踪的远程分支合成一个标签，条件是上游指向的远程分支在同一个提交上，显示成 `origin & develop`。
- 顺序：游离 HEAD → 当前分支 → 其它本地分支 → 远程分支 → tag，同类按名字。
- 不出 `origin/HEAD` 的标签（2026-10-22 项目负责人定），理由同分支树（`product/features/branches.md`「分支树」）。
- 标签名超过 22 个字时，把第一个 `/` 前面换成 `..`，剩下的交给 CSS 省略号。不量文字宽度：代价是窄屏时可能比必要的截得多一点。放不下时从后往前收缩，每个标签最窄只剩图标。否决只显示前几个、其余写 `+N`：多了一个悬停交互。
- 外观：无边框，字号小一档；用 codicon 区分类型，图标按主题色着色：当前分支 `charts.yellow`，本地 `charts.green`，远程 `charts.purple`，tag `descriptionForeground`，detached HEAD 用 `warning` 图标加 `editorWarning.foreground`。

目标是扫一眼就看出分支头的分布，不照抄 IDEA 的吊牌。否决过：
- 边框盒子：图标本身已经起了分隔的作用，加框多占宽度，在 22px 的行高里显得重。
- 照 IDEA 自画吊牌并叠画（HEAD 黄 + 本地绿 + 远程紫）：要自绘 SVG 和遮罩挖空（行背景随悬停、选中变化，不能填底色），而要看出分支头的分布，颜色加文字已经够了。留在需求池。
- IDEA 写死的颜色：浅色主题上黄色看不清，高对比主题不合规；`charts.*` 每个主题都有。
- 按宽度把放不下的那组收成一个叠画图标：要逐行量文字宽度，虚拟列表里还要随宽度重算；CSS 的收缩系数已经能做到「前面的优先」。
- 按名字猜跟踪关系（IDEA 在没有 upstream 时找 `<远程>/<本地名>`）：`Ref.upstream` 已经回答了谁跟踪谁。

## 鼠标

点图上任何位置，都等于选中这一行，和点 Message 一样。节点和线不单独响应点击、不加粗、不显示悬停提示。否决照 IDEA 点节点加粗相连的线：需求里没有，也不进需求池。

## 实现

```
getSkeleton ──► 骨架 ─┐
getRefs ──────► refs ─┼─► ① 图结构、编号、颜色（骨架或 refs 变了才重算）
                      │            │
筛选 ──► hash 列表 ───┴────────────┴─► ② 可见图（筛选变了才重算：虚线、截断）
                                                │
                                                ▼
                                       ③ 每行的元素与位置、行宽、基准
                                                │
                              CommitList.vue ◄──┘  只画可见那几十行的 SVG
refs ─► ④ 标签分组（按提交 hash）──► CommitList.vue  Message 单元格右侧
```

- ①②③④ 都是 `webview/src/logic/log/graph/` 与 `refLabels.ts` 里的纯函数，不 import Vue，在纯 node 下测。扩展侧和协议不为图做任何改动。
  | 文件 | 做什么 |
  |---|---|
  | `structure.ts` | 骨架转成按行号的图：每行的父行号、子行号；父提交不在骨架里的记作「缺失」 |
  | `layout.ts` | 头的排序，加上沿第一父提交编号 |
  | `color.ts` | 颜色 id：只给身份，不取余 |
  | `visible.ts` | 筛选后的可见图：直接父子相连是实线，中间隔着被藏的提交是虚线，缺失或找不到可见祖先记作渐隐。不筛选时就是「全部可见、全是实线」，走同一条路 |
  | `rows.ts` | 每行有哪些元素、长线只留两头、按编号排序得位置、相邻行的目标位置、行宽、推荐宽度与基准 |
- 全部行一次算完，不按可见行懒算：推荐宽度本来就要用到所有行的宽度。一万条的耗时见 `tech/performance.md`。
- 渲染：每行最左边一个 `<svg>`；每段线一条 `<path>`（箭头的两翼也在同一条里），节点一个 `<circle>` 最后画、盖在线上。虚线用 `stroke-dasharray`；渐隐的那段配一条自己的 `linearGradient` 当描边。颜色用内联 `style`（SVG 属性里的 `var()` 不保证生效）。线不做像素对齐。
- **骨架没变就沿用旧数组**（同 vscode-git-graph）：refs 过期时照样重拉骨架，逐条比较 hash、父提交和提交时间，全都相同就沿用旧数组，图不重算、筛选也不重查。省的是 webview 这边，不省 `git log` 和传输。否决「ref 指向的 hash 集合没变就不拉」：`shallow`、`refs/replace` 不动 ref 也会改图。否决 IDEA 的增量拼接：拼接与回退的逻辑远超收益。
