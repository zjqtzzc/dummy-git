# Log 面板

> 底部的 Log 面板：三栏布局、提交列表、提交详情、过滤与搜索、复制、提交的右键菜单，以及为什么这样做。改 `webview/src/log/`、`logic/log/` 与相关的 git 命令前先读本文；行为变了就改本文。
> 左栏分支树见 `product/features/branches.md`；提交图与 ref 标签见 `product/features/graph.md`；右栏的文件树与打开 diff 见 `product/features/trees.md`。

## 面板与三栏

- 底部面板的视图容器标题 `Dummy Git`，里面一个视图 `Log`，图标是一个提交图形的简单 SVG。界面文字全部英文。
- 三栏：左边分支树、中间提交列表（上面是过滤栏）、右边是选中的提交（上面是它改了的文件，下面是详情）。宽度全用像素：左 240px、右 320px，中间占剩下的全部。拖动分隔线后的左右宽度存进 `setState`，收起再展开、重新加载窗口都会恢复；窗口大小变化时左右两栏宽度不变。
  - 实现：两层 `vscode-split-layout`，外层 `fixed-pane="start"`、内层 `fixed-pane="end"`。内层的分隔线只能从左边定位，所以挂载后先量出总宽度，再放到「宽度 − 右栏宽度」的位置。
- **右栏上下按比例分**（同 IDEA 的 `OnePixelSplitter`，比例 0.7）：默认文件占 70%，面板变高变矮时上下一起伸缩；拖过的比例存进 `setState`。否决固定详情的像素高度：左右栏固定宽度是为了让中间的提交列表吃掉多出的空间，右栏上下没有这个理由。
  - 实现：这一层不设 `fixed-pane`。这时组件不跟踪尺寸，内部记的分隔线像素位置和总高度都会过时，面板改过大小后一按分隔线就跳位；所以由我们监听尺寸变化，每次按比例重设 `handlePosition`（它会先重新量总高度）。不能用 `resetHandlePosition()`：它只重算位置、不更新总高度，比例会越拉越歪。

## 提交列表

- 三列：**Message** 只显示第一行；**Author** 只显示名字；**Date** 用作者时间：一小时以内写「多久之前」（`just now`、`5 minutes ago`），今天更早的写 `Today 11:23`，再早的写年月日加时分（`2026/9/20 15:51`）。所有显示时间的地方都是这一种写法（`logic/utils/time.ts`）。
- **列宽**：表头有两条分界线。拖 Message|Author 只改 Author；拖 Author|Date 时两列此消彼长，Message 不动。拖过之后，把像素宽度存进 `viewState`；没拖过时用 CSS 的 `8em` / `9.5em`，跟着字号走。开始拖时先量表头的实际宽度，所以 em 和像素之间是无缝的。否决默认值也写成像素：就丢了跟字号缩放。否决 Author|Date 只改 Date：拖它时 Author 整列会跟着平移，手感不对。
- **最多一万条**，更早的不取。不设上限的话，18.8 万条的仓库要常驻约 360 MB，更大的仓库会让扩展宿主内存溢出。第一万条附近的父提交不在列表里，提交图上那条线画到行底并渐隐。
- **取数模型**：先拉全部骨架（hash、父提交、时间，窄字段），用来建图和排顺序；用户看到哪几行，再按 hash 去取那几行的详情（说明、作者等）。可见范围前后再多取一些，缓存起来。还没取到详情的行，三列先显示浅色占位。骨架是本项目最重的一条只读命令（vscode 仓库上约 1.6 秒），要避免频繁重跑。
- 虚拟滚动：行高固定 22px，只渲染看得见的几十行。
- 打开时选中 HEAD 所在的提交并滚到它（第一行不一定是 HEAD）。
- **刷新**（新提交、切换分支）：选中的提交还在列表里就保持选中，并让它停在屏幕上原来的位置（上面多了新提交时视图不跳）；不在了就改选 HEAD 所在的提交。右栏只在选中变了时才重取。
- 首次加载时中间栏显示 `Loading…`；右栏取文件时也显示 `Loading…`。

## 提交详情

右栏下半部分，同 IDEA 的提交详情：
```
标题（加粗）
正文（照原样，保留换行）
1a2b3c4  Alice <alice@x.com>  2026/9/20 15:51
committed by Bob <bob@x.com>  2026/9/21 09:00     ← 灰色
```
- **标题**是说明的第一段（到第一个空行为止）；第一段本身有好几行时不算标题，整段说明都照正文排（同 IDEA）。不照 IDEA 按标题右边距折开长标题：自然换行就够了。
- **元信息**：短 hash、`名字 <邮箱>`（邮箱为空时只写名字）、作者时间。日期写绝对时间，和复制提交时同一种写法；不照 IDEA 的 `on … at …` 句式，界面别处都是短写法。
- **提交者一行**（灰色）：提交者和作者不是同一个人时写 `committed by …`；同一个人（名字和邮箱都相同）、只是时间不同（rebase、amend 过）时写 `committed <时间>`；都一样就没有这一行。
- 文字可以选中复制；长单词（URL、路径）在任意处折行。说明里的 hash、URL 不做成链接。
- 只用已经按 hash 取到的提交详情，不加 git 命令；没有选中、或详情还没取到时留空。
- 不显示这条提交上的分支和 tag（列表那一行已经有了），也不显示包含这条提交的分支（`product/backlog.md`）。

## 过滤与搜索

提交列表正上方一行，只占中间那栏（同 IDEA）：左边搜索框占满剩余宽度，右边 `Branch`、`User`、`Date`、`Paths` 四个按钮。未生效时按钮只写名字，生效后写当前的值（`User: Me`），后面带 × 用来清除。中间栏变窄时，先缩搜索框，按钮文字不截断。

- **选值用 VS Code 原生的 QuickPick**（由扩展弹出，可搜索，键盘和主题都是原生的），选中的值交回页面，过滤状态由页面持有。以后换成按钮正下方的下拉菜单（`product/backlog.md`），到时只换弹框这一层。
- **分支**：单选。Branch 按钮弹出本地与远程分支；左栏双击分支效果一样（HEAD 那行是当前分支）。分支过滤是换骨架的起点、重取一万条。正在过滤的分支被删掉时，过滤自动清除，按全部分支重取。
- **作者**：单选。第一项是 **Me**（git 配置里的 `user.name` 与 `user.email`），下面是这一万条里出现过的作者，按提交数从多到少排。按「名字 <邮箱>」整串、当作普通文字匹配（`--author` + `-F`），不用正则。
- **日期**：`Last 24 Hours`、`Last 7 Days`、`Last Month` 三个预设，不做自定义。在页面里按骨架的时间筛，不问 git。
- **路径**：列出所有被跟踪的文件，以及由它们推出的目录，可搜索，单选；`git log -- <路径>`，不跟改名（不加 `--follow`）。
- **搜索框：说明文字或 hash**（同 IDEA 的「Text or hash」），两路结果取并集：
  - 说明文字：普通文字，不分大小写（`--grep` + `-F -i`）；
  - hash：输入是 4 个以上的十六进制字符时，也匹配以它开头的 hash（在页面里对骨架做）。4 是 git 缩写的最短长度，免得 `add`、`fix` 这类短词误中。
  - 停止输入 300 毫秒后才查；查询进行中旧列表留着，过滤栏右边转圈；只收最新那次查询的结果。
- **组合**：几种过滤取交集（同 IDEA）。过滤只在骨架那一万条里做：`git log --no-walk --stdin` 加上条件，一次一个条件，页面取交集。一万条以上的仓库上几种过滤都在 100 ms 以内（`tech/performance.md`）。
- 过滤后，原来选中的提交还在就保持选中，不在就清空选中；分支过滤照骨架刷新的规则。没有结果时正中一行灰字 `No commits match the filters`。仓库变化时自动重查。过滤条件存进 `viewState`。
- 筛选时提交图怎么画，见 `product/features/graph.md`。

## 复制

- 提交列表上 Ctrl+C（Mac 上 Cmd+C）：复制选中提交的完整说明，空一行，再是 `Author: 名字 <邮箱>`、`Date: 2026/9/20 09:05` 两行。日期写绝对时间：贴出去的文字不该写「5 minutes ago」。
- 提交行右键 **Copy Hash**：完整 hash。
