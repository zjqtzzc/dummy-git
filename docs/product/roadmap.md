# 路线图

> 有哪些阶段、各阶段做什么、做到哪了。只写做什么，不写怎么做：交互细节在 `features/`（正在做的在 `../phases/`）。
> 开一个新阶段、结束一个阶段时改本文（`../process/workflow.md` §2）。还没排进阶段的在 `backlog.md`，永远不做的在 `never.md`。

一条需求进不进某阶段，只看：没有它，这一阶段的验收句还成不成立。

## 阶段骨架

| # | 名字 | 验收句 | 为什么排在这里 |
|---|---|---|---|
| 1 | 只读 Log | 底部面板打开，看到提交列表和分支，点一条看到改了哪些文件，用 VS Code 自带的 diff。不画图，不提交，不切分支，不推送。 | 只读，不碰工作区，最先能用。 |
| 2 | 提交 | 侧栏 Commit 面板打开，看到未提交的文件树，勾选文件、写说明，提交或 Amend；勾选后 Rollback 直接删除已跟踪文件的改动。提交后底部 Log 自己出现新提交。不推送，不 stash，不切分支。 | 第一个写操作，只改当前目录，不会产生冲突。 |
| 3 | 和远程同步 | Log 面板左边的按钮区点拉取，能快进就快进，不能快进就显示 git 的报错；点推送，把当前分支推到唯一的远程，新分支自动带 `-u`。左栏分支显示 ahead/behind。不 merge，不 rebase，不 force push；新分支要选远程而无法判断（多个远程且没有 origin）时报错。 | 补上「提交→推送」这个日常闭环。要密码时先报错，输入密码在第 6 阶段。 |
| 4 | 分支与 Stash | 左栏分支右键可以切换、新建、重命名、删除；Commit 面板切到 Stash，一键存、Pop、Apply、删除。切不过去时显示 git 的报错。不 merge，不 rebase。 | 都是本地操作，不会停在半路。 |
| 5 | 在 Log 里找 | 按分支、作者（含 Me）、日期、路径过滤；搜索框按说明文字或 hash 搜索；复制提交信息。 | 只读，排在写操作的复杂部分之前。 |
| 6 | 输入密码 | 拉取、推送、Fetch 要账号密码或 SSH 口令，以及 SSH 签名要口令时，插件弹框让人输入，输完操作接着完成。GPG 签名始终交给系统的 pinentry。 | 前面阶段遇到要密码一律报错；后面 rebase、cherry-pick 也会产生要签名的提交，所以排在它们前面。**推迟**（2026-10-09，用户眼下用不到）：先做第 7 阶段，那时要密码或签名口令的操作照旧显示 git 的报错。 |
| 7 | 会停在半路的操作 | merge、rebase（到分支或任意提交）、不能快进的拉取、cherry-pick、revert。停在半路时，冲突组的标题行写明是哪种操作，右边给继续和放弃（2026-10-10 改：原为 Commit 面板顶部横幅）；冲突文件用 VS Code 自带的合并编辑器解决。 | 这些操作共用「停在半路」的处理（冲突组标题行的继续与放弃），必须一起做。第 3 阶段的拉取到这里才补全；推送被拒照旧报错（选 rebase 或 merge 进了需求池）。 |
| 8 | 提交图 | 列表左边加 Graph 列，画出分支和合并的线，ref 标签跟在提交上。 | 只读，可以挪到任何位置。放在 merge/rebase 之后，线才有意义。 |
| 9 | 改写历史 | reset（soft / mixed / keep / hard，撤销最近几次提交也用它）。二次确认。reword、squash、fixup、force push 要自定义弹出窗口，drop 也暂缓，都进池子（2026-10-15）。 | 会丢东西。交互式 rebase 会停在半路，依赖第 7 阶段。 |
| 10 | 推送对话框 | 分支右键 `Push…` 打开推送对话框（编辑器标签页），看到要推的提交，可改远程和远程分支名，Push 的下拉里可选 Force Push（force-with-lease）；没有远程时在对话框里定义远程。 | 自定义弹出窗口的原型：通用外壳与控件在这里验证，再搬给 reword、squash 等（2026-10-15）。 |
| 11 | Reword | 提交右键 `Edit Commit Message…` 打开对话框，改一条提交的说明，点 Reword 后在内存里重造那条与它后面的提交，工作区不动。squash 等提交列表多选，仍在池子（2026-10-15）。 | 第二个对话框，验证外壳能复用；只改说明的改写不会冲突，先做。 |
| 12 | 操作日志 | 出事以后，看「输出」里的 Dummy Git 就能还原：在什么环境（git 版本、远程类型）、谁从哪个入口做了什么、确认框问了什么答了什么、跑了哪些 git 命令（含 stderr）、结果是什么、哪一步慢。 | 2026-10-16 一次 stash 被删、一次 stash 展开为空，日志都没能直接回答；之后每个功能出问题都靠它，排在多选之前。 |

## 各阶段做什么

### 第 1 阶段 · 只读 Log

- Log 放在 VS Code 底部面板。
- 界面上的文字全部用英文（列标题、相对时间、提示信息），后面各阶段沿用。
- 三栏：左分支、中提交列表、右文件。分隔条可拖。没有按钮区。
- 左栏、右栏是固定像素宽度（默认 240 / 320），中间占剩下的全部。拖动后的栏宽记住，收起再展开、重新加载窗口后都保留；窗口或面板大小变化时只有中间伸缩。
- 左栏：顶上一行 HEAD（当前分支）；「本地」一组；「远程」一组，先按远程名分，组内按 `/` 折叠成目录。
- 中间列表固定三列：Message、Author、Date。不显示 Hash，列不可隐藏。Author、Date 列宽可拖（2026-10-14 改，原为不可拖），拖过的宽度记住；Message 占剩下的全部。
- 日期用作者时间：一小时以内写成「多久之前」，今天更早的写成 `Today 11:23`，再早的写成年月日加时分。所有显示时间的地方（Log、Stash 列表…）同一种写法。
- 提交列表最多一万条。超过一万条的仓库只显示最近的一万条，更早的不显示。
- 右栏：选中提交改了哪些文件，按目录树显示。
- 文件按类型显示图标，样子和 VS Code 默认的 Seti 图标主题一样。后面各阶段的文件树沿用。
- 从右栏打开一个文件，用 VS Code 自带的 diff 编辑器看这次提交前后的对比。插件自己提供读取任意历史版本的内容。
- 所有文件树（本阶段的右栏，以后的 Commit 面板、Stash）：双击或回车打开 diff；单击或方向键只选中，但插件的 diff 标签正显示在前台时，diff 跟着换成选中的文件，焦点留在文件树。
- 插件打开的 diff 始终只占一个标签页，打开新的就关掉旧的。VS Code 自己和其它扩展打开的 diff 不管。
- 选中合并提交时，右栏文件树为空。
- 没有打开目录、打开的目录都不是 git 仓库、或者 git 无法运行时，底部和侧栏两个面板照常显示，内容区写明原因，并提示处理后重新加载窗口。不弹通知，不提供初始化仓库。

### 第 2 阶段 · 提交

- Commit 面板放在侧栏。
- 未提交的文件按目录树列出，未跟踪文件逐个列出，不折叠成目录。
- 文件和目录都有复选框，勾目录等于勾它下面全部。
- 文件变化引起刷新时，勾选状态保持不变。
- 所有树（Log 左栏分支树、右栏文件树、Commit 面板，以后的 Stash）收起一个目录时，它下面的子目录一起收起；再展开只露出一层。
- 写说明，提交；可切到 Amend，改最近一次提交。
- 勾选后点 Rollback，先弹一个简单确认（文件数 + 前 5 个文件名），确认后已跟踪文件的改动直接删除，恢复成 HEAD 的样子，不进回收站，不能恢复。新增过的文件连磁盘上的一起删。Rollback 不管未跟踪文件（它们用第 7 阶段右键菜单里的 Delete）。
- 工具栏在这一阶段只有 Rollback 与全部展开 / 收起；Commit 按钮在面板底部。
- 提交需要输入密码时，插件自己不弹框：SSH 签名口令直接报错；GPG 签名交给系统的 pinentry，系统弹不出来就报错。

### 第 3 阶段 · 和远程同步

- 分支栏左边加一条竖的按钮区，这一阶段放 Fetch、Pull、Push 三个按钮（同 IDEA 的 Log 窗口；Commit 面板不放同步操作）。2026-10-14 改为从上到下 New、Update、Delete、Fetch，Push 只在右键菜单。Fetch 时顺带清掉远程已删除的分支。
- 更新（Update，2026-10-14 由 Pull 改名，同 IDEA 的 Update Selected）：针对分支树里选中的本地分支（HEAD 那行即当前分支），只更新它和它跟踪的远程分支，不动别的分支。能快进就快进，不能就显示 git 的报错（以后转进合并界面，见池子）。
- 推送分支树里选中的本地分支到它跟踪的远程分支。新分支第一次推送自动带 `-u`，远程按「唯一的远程 → `origin`」选，都不成立就报错。
- 按钮的提示文字写明作用对象：`Fetch`、`Update Selected`、`Delete Selected`、`New Branch from Selected`。
- 左栏分支旁显示 ahead/behind 数量。
- 耗时操作要让人看见「正在做 / 做完了」。
- 推送被拒时，显示 git 的报错。
- 拉取或推送需要输入账号密码或 SSH 口令时，直接报错，不等待。

### 第 4 阶段 · 分支与 Stash

- 左栏分支右键：切换、从这里新建分支、重命名、删除。
- Commit 面板顶上切换 Commit / Stash 两种模式。
- Stash 模式：列出全部 stash，时间写法和 Log 一样。
- Commit 面板一键存，不问名字：勾了文件存勾选的（勾了未跟踪文件也一起存），什么都没勾存全部。
- 对一条 stash：Stash 模式工具栏有 Apply、删除；右键菜单有 Pop、Apply、删除。
- 切换失败（有未提交改动、分支被别的 worktree 占用等），显示 git 的报错。

### 第 5 阶段 · 在 Log 里找

- 按分支过滤。左栏双击一个分支，Log 就筛选成这个分支。
- 按作者过滤，其中有一项 Me。
- 按日期过滤：24 小时、7 天、一个月。
- 按路径过滤，只看某个目录或文件的历史。
- 搜索框按说明文字或 hash 搜索。
- 复制快捷键复制说明、作者和日期；右键另有「复制 hash」。分支树上复制快捷键复制分支名。

### 第 6 阶段 · 输入密码

- 拉取、推送、Fetch 需要账号密码或 SSH 口令时，插件弹框输入，操作接着完成。
- SSH 签名需要口令时，插件弹框输入，提交接着完成。
- 首次连接要确认主机指纹时，插件弹框让人选是或否。
- GPG 签名始终交给系统的 pinentry，插件不接管。
- 输入框取消，操作按失败处理，显示 git 的报错。

### 第 7 阶段 · 会停在半路的操作

- 分支右键：合并到当前分支、把当前分支 rebase 到它。
- 提交右键：rebase 到这条提交、cherry-pick、revert。
- 不能快进的拉取，分成「rebase 方式」和「merge 方式」两个入口：拉取遇到分叉时，通知里给这两个按钮。
- 停在半路时，冲突组的标题行写明是哪种操作停了，右边给继续和放弃。放弃按操作类型分别调用对应的 abort。（2026-10-10 改：原为 Commit 面板顶部横幅）
- 停在半路时（merge、rebase、cherry-pick、revert），说明框预先填好 git 准备的说明。（2026-10-10 改：原为只有合并停下时预填）
- 冲突文件在 Commit 面板里单独成一组，没有复选框。
- 冲突文件用 VS Code 的合并编辑器打开。
- 没有进行中的操作、但有未合并的文件时（比如 stash 取出时冲突），同样显示冲突组。
- 冲突文件能标记为已解决。文件里还有冲突标记时，先确认再标记。标记后移出冲突组。
- 一边删了、一边改了的冲突，不开合并编辑器，直接选「保留」或「删除文件」。两边都删了的只能删。
- 冲突组没清空时不能继续。继续时不自动把其它文件标记为已解决。
- Commit 面板文件的右键菜单在这一阶段接入；未跟踪文件右键 Delete（确认后从磁盘删掉）一起做。

### 第 8 阶段 · 提交图

- 列表最左加 Graph 列，自己画，不用第三方图库。图画在 Message 单元格最左边，每行文字按本行图的宽度退让，基准宽度最多 6 条车道（同 IDEA，2026-10-14 定）。
- 连线走折角，不用曲线。
- 长线只画两头、带箭头，中间不画也不占位置（同 IDEA，2026-10-14 从池子挪进来：不隐藏长线，图的宽度基准形同虚设）。
- 列表分页加载时，图要接得上。
- ref 标签（分支、tag）显示在对应提交上，靠右；本地分支和它跟踪的远程分支合成一个标签（同 IDEA，2026-10-14 从永不做拿出来）。
- 按作者、说明文字、路径、日期筛选时，只显示匹配的提交；两条匹配的提交之间隔着被跳过的提交时，画虚线相连。

### 第 9 阶段 · 改写历史

- reset 到某条提交：soft / mixed / keep / hard 四种，都要二次确认。
- 撤销最近一次提交，改动留在工作区。（用 Reset → Soft 完成，不单设入口）
- 把最上面几条提交弹出去，改动留在工作区。（同上）

### 第 10 阶段 · 推送对话框

（2026-10-15 从池子移入；细节见 `phases/phase-10.md`）
- 所有推送走推送对话框（分支右键；以后推送被拒后的重推、`Push All up to Here…` 也接到这里）。
- 可选远程、改远程分支名。
- 预览要推的提交。
- force push（force-with-lease）。
- 没有远程时可定义远程。
- 选仓库不做（现阶段只支持单仓库）。

### 第 11 阶段 · Reword

（2026-10-15 从池子移入；细节见 `phases/phase-11.md`）
- 改某一条历史提交的说明。只在这条到 HEAD 是一条没有合并提交的直线时可用。

### 第 12 阶段 · 操作日志

（2026-10-16 从池子移入；细节见 `phases/phase-12.md`）
- 启动与找到仓库时记运行环境。
- 每个操作（webview 请求或右键菜单命令）记开头与结尾：编号、入口、命令、参数、结果摘要或错误、用时；它跑的 git 命令与问用户的问答带同一编号。
- git 命令的 stderr 照记；超过 1 秒的标慢。
- 仓库变化引起的刷新记一行；webview 里的异常也记进来。
