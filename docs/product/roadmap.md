# 路线图

> 有哪些阶段、做到哪了。只写做什么，不写怎么做：交互细节在 `features/`（正在做的在 `../phases/`）。
> 开一个新阶段、结束一个阶段时改本文（`../process/workflow.md` §2）。做完的阶段只留阶段表里一行；还没排进阶段的在 `backlog.md`，永远不做的在 `never.md`。

一条需求进不进某阶段，只看：没有它，这一阶段的验收句还成不成立。

## 阶段骨架

| # | 名字 | 状态 | 验收句 | 为什么排在这里 |
|---|---|---|---|---|
| 1 | 只读 Log | 完成 | 底部面板打开，看到提交列表和分支，点一条看到改了哪些文件，用 VS Code 自带的 diff。不画图，不提交，不切分支，不推送。 | 只读，不碰工作区，最先能用。 |
| 2 | 提交 | 完成 | 侧栏 Commit 面板打开，看到未提交的文件树，勾选文件、写说明，提交或 Amend；勾选后 Rollback 直接删除已跟踪文件的改动。提交后底部 Log 自己出现新提交。不推送，不 stash，不切分支。 | 第一个写操作，只改当前目录，不会产生冲突。 |
| 3 | 和远程同步 | 完成 | Log 面板左边的按钮区点拉取，能快进就快进，不能快进就显示 git 的报错；点推送，把当前分支推到唯一的远程，新分支自动带 `-u`。左栏分支显示 ahead/behind。不 merge，不 rebase，不 force push；新分支要选远程而无法判断（多个远程且没有 origin）时报错。 | 补上「提交→推送」这个日常闭环。要密码时先报错，输入密码在第 6 阶段。 |
| 4 | 分支与 Stash | 完成 | 左栏分支右键可以切换、新建、重命名、删除；Commit 面板切到 Stash，一键存、Pop、Apply、删除。切不过去时显示 git 的报错。不 merge，不 rebase。 | 都是本地操作，不会停在半路。 |
| 5 | 在 Log 里找 | 完成 | 按分支、作者（含 Me）、日期、路径过滤；搜索框按说明文字或 hash 搜索；复制提交信息。 | 只读，排在写操作的复杂部分之前。 |
| 6 | 输入密码 | 推迟 | 拉取、推送、Fetch 要账号密码或 SSH 口令，以及 SSH 签名要口令时，插件弹框让人输入，输完操作接着完成。GPG 签名始终交给系统的 pinentry。 | 前面阶段遇到要密码一律报错；后面 rebase、cherry-pick 也会产生要签名的提交，所以排在它们前面。**推迟**（2026-10-09，用户眼下用不到）：先做第 7 阶段，那时要密码或签名口令的操作照旧显示 git 的报错。 |
| 7 | 会停在半路的操作 | 完成 | merge、rebase（到分支或任意提交）、不能快进的拉取、cherry-pick、revert。停在半路时，冲突组的标题行写明是哪种操作，右边给继续和放弃（2026-10-10 改：原为 Commit 面板顶部横幅）；冲突文件用 VS Code 自带的合并编辑器解决。 | 这些操作共用「停在半路」的处理（冲突组标题行的继续与放弃），必须一起做。第 3 阶段的拉取到这里才补全；推送被拒照旧报错（选 rebase 或 merge 进了需求池）。 |
| 8 | 提交图 | 完成 | 列表左边加 Graph 列，画出分支和合并的线，ref 标签跟在提交上。 | 只读，可以挪到任何位置。放在 merge/rebase 之后，线才有意义。 |
| 9 | 改写历史 | 完成 | reset（soft / mixed / keep / hard，撤销最近几次提交也用它）。二次确认。reword、squash、fixup、force push 要自定义弹出窗口，drop 也暂缓，都进池子（2026-10-15）。 | 会丢东西。交互式 rebase 会停在半路，依赖第 7 阶段。 |
| 10 | 推送对话框 | 完成 | 分支右键 `Push…` 打开推送对话框（编辑器标签页），看到要推的提交，可改远程和远程分支名，Push 的下拉里可选 Force Push（force-with-lease）；没有远程时在对话框里定义远程。 | 自定义弹出窗口的原型：通用外壳与控件在这里验证，再搬给 reword、squash 等（2026-10-15）。 |
| 11 | Reword | 完成 | 提交右键 `Edit Commit Message…` 打开对话框，改一条提交的说明，点 Reword 后在内存里重造那条与它后面的提交，工作区不动。squash 等提交列表多选，仍在池子（2026-10-15）。 | 第二个对话框，验证外壳能复用；只改说明的改写不会冲突，先做。 |
| 12 | 操作日志 | 完成 | 出事以后，看「输出」里的 Dummy Git 就能还原：在什么环境（git 版本、远程类型）、谁从哪个入口做了什么、确认框问了什么答了什么、跑了哪些 git 命令（含 stderr）、结果是什么、哪一步慢。 | 2026-10-16 一次 stash 被删、一次 stash 展开为空，日志都没能直接回答；之后每个功能出问题都靠它，排在多选之前。 |
| 13 | 提交详情 | 完成 | Log 右栏上下分开：上面是选中提交改了的文件，下面是它的详情（完整说明、hash、作者与邮箱、日期；提交者不同时另起一行）。 | 只用已经取到的数据，不加 git 命令；先补齐看一条提交最基本的信息。 |
| 14 | 提交列表多选 | 完成 | Log 的提交列表能一次选中多条；选中多条后，右键能一起复制 hash、cherry-pick、revert。 | 多选的选中规则和「右键菜单拿到整个选中」先在一处列表上跑通，第 15 阶段的树直接接上。 |
| 15 | 树的多选 | 完成 | 分支树和 Commit 面板的文件能一次选中多个；右键目录或分组，等于对它下面的全部。分支能批量删除、更新；Commit 面板的 Rollback、Add to Git、Delete 作用于选中的项，什么都没选时 Rollback 作用于全部改动。 | 用第 14 阶段的选中规则与菜单做法；和第 14 阶段合起来超过 8 步，拆开（2026-10-19）。 |
| 16 | Log 高亮 | 完成 | 提交列表里，我的提交作者加粗，合并提交文字变灰，当前分支上的提交带一层浅色背景；过滤栏右边的按钮能分别开关这三种。 | 只改样式、不加写操作；骨架里现成的数据就能算出大半（2026-10-21 项目负责人提）。 |
| 17 | 图标按钮的选单 | 完成 | 工具栏上点开会弹选单的图标按钮，右下角带一个小三角；点开是贴着按钮的浮层选单，上下左右都不超出面板，点外面或按 Esc 收起。View Options 用它开关三种高亮。 | 原生 QuickPick 从窗口顶部正中弹出、离按钮太远；以后还有带二级选单的按钮，先把写法统一（2026-10-21 项目负责人提）。 |
| 18 | 视图选项 | 完成 | Commit 面板与 Stash 各有一个 View Options 按钮，能关掉「按目录分组」，文件直接平铺；Log 过滤栏有一个 Graph Options 按钮，能在「按提交时间」和「拓扑」两种排序之间切换。 | 用上第 17 阶段的浮层选单；都只改怎么显示（2026-10-22 项目负责人提）。 |

## 还没做完的阶段

### 第 6 阶段 · 输入密码

- 拉取、推送、Fetch 需要账号密码或 SSH 口令时，插件弹框输入，操作接着完成。
- SSH 签名需要口令时，插件弹框输入，提交接着完成。
- 首次连接要确认主机指纹时，插件弹框让人选是或否。
- GPG 签名始终交给系统的 pinentry，插件不接管。
- 输入框取消，操作按失败处理，显示 git 的报错。
